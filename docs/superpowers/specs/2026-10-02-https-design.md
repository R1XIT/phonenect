# Шифрование всех соединений Phonenect (HTTPS)

Дата: 2026-10-02. Статус: одобрено в обсуждении, ждёт проверки спецификации.

## Зачем

Сейчас телефоны и ПК общаются по HTTP без шифрования. Любой в той же сети Wi-Fi видит содержимое буфера,
файлы и токен доступа, а с токеном получает полный доступ. Цель — чтобы перехват в сети ничего не давал:
ни содержимого, ни токена, ни возможности выдать себя за ПК.

Решение пользователя: **HTTPS везде**, HTTP с токеном выключается полностью. На iPhone ради этого допустим
один дополнительный шаг — установка профиля с сертификатом.

## Критерии успеха

1. Ни один запрос с токеном или содержимым буфера не идёт по HTTP.
2. Android-приложение и связанные ПК соединяются только с «своим» ПК: подменный сервер с любым другим
   сертификатом отвергается, даже если у него правильное имя или IP.
3. iPhone (Safari и «Быстрые команды») работает по HTTPS после установки профиля.
4. Смена IP ПК не требует ничего переустанавливать на телефонах.
5. Уже подключённые устройства получают понятное сообщение «переподключите», а не молча перестают работать.

## Устройство

### 1. Сертификаты (новый модуль `phonenect/certs.py`)

- При первом запуске ПК создаёт свой **удостоверяющий центр** (CA): ключ EC P-256, срок 10 лет,
  `BasicConstraints(ca=True)`, имя «Phonenect <имя ПК>». Хранится в `%APPDATA%\phonenect\ca.pem` и `ca.key`.
- Им подписывается **сертификат сервера**: ключ EC P-256, срок 397 дней (iOS принимает не больше 825),
  `ExtendedKeyUsage(serverAuth)`, в SAN — текущий IP, `127.0.0.1`, `localhost`, `phonenect-<id>.local`,
  `phonenect.local`. Хранится в `server.pem` / `server.key`.
- Сертификат сервера **перевыпускается**, если в нём нет текущего IP или до конца срока меньше 30 дней.
  Проверка — при запуске и при смене IP (раз в минуту, как у mDNS). Новый сертификат подхватывается для новых
  соединений без перезапуска (`ssl.SSLContext.load_cert_chain` на том же контексте).
- **Отпечаток** — SHA-256 от DER сертификата CA, в шестнадцатеричном виде. Показывается на странице подключения,
  передаётся в ссылках как `fp=…`.
- Зависимость: пакет `cryptography`.

### 2. Порты (`server.py`, `__main__.py`)

- **8765 — HTTPS.** Всё как сейчас: API, `/ws`, веб-клиент, `/pair` (по-прежнему только с самого ПК).
- **8766 — HTTP, «стартовая страница».** Только то, где нет секретов:
  `GET /` (страница с инструкцией и ссылкой на шаг 2), `GET /ca.mobileconfig` (профиль iOS с CA),
  `GET /ca.crt` (CA для Android и других), `GET /android/phonenect.apk`, `GET /shortcuts/*.shortcut`, `/icon.svg`.
  Любой другой путь — 404. Токен здесь не принимается и не выдаётся.
- Порт 8766 задаётся в config.json как `setup_port`.

### 3. Ссылки подключения

- Ссылка для телефона: `phonenect://pair?url=https://IP:8765&t=TOKEN&name=…&fp=ОТПЕЧАТОК`.
- Адрес API (веб-клиент, команды iPhone, связь ПК): `https://host:8765/api/clip?t=TOKEN&fp=ОТПЕЧАТОК`.
  `fp` браузеру и iPhone не мешает (лишний параметр), а приложению и ПК нужен для проверки.
- Страница `/pair` показывает два QR-кода: «Шаг 1 — сертификат» (`http://IP:8766/`) и
  «Шаг 2 — подключение» (`https://IP:8765/?t=…`), и отпечаток CA.

### 4. Android-приложение

- `Pc` получает поле `fp`. Ссылка без `fp` или с `http://` не принимается («Старая ссылка — отсканируйте QR-код
  с ПК заново»).
- Свой `OkHttpClient` для каждого ПК: доверяет только сохранённому сертификату CA этого ПК (как он получается —
  следующий пункт); проверка имени хоста отключена, потому что CA уникален для ПК и подписывает только его
  сервер, а IP меняется.
- **Как приложение получает сам сертификат CA:** при подключении по ссылке скачивает `http://IP:8766/ca.crt`
  и сравнивает его SHA-256 с `fp` из ссылки. Не совпало — отказ. Совпало — сохраняет сертификат вместе с ПК.
  (Ссылка пришла по доверенному каналу — QR с экрана или USB, — поэтому подменить CA нельзя.)
- Загрузка файлов — своей службой через OkHttp в «Загрузки/Phonenect» (MediaStore на Android 10+, папка
  приложения на 8–9) с уведомлением о ходе и кнопкой «Открыть». DownloadManager больше не используется.
- Миграция: ПК с адресом `http://` в списке помечаются «нужно переподключить»; служба к ним не подключается,
  экран показывает подсказку.
- USB-настройка (`android_setup.py`) передаёт новую ссылку с `https` и `fp`.

### 5. Связь ПК между собой (`peers.py`)

- Адрес другого ПК обязан содержать `fp`. При связывании ПК скачивает `http://host:8766/ca.crt`, сверяет с `fp`,
  сохраняет CA в config.json вместе со связью и дальше доверяет только ему (`ssl.SSLContext` с `cadata`,
  `check_hostname=False`).
- Старые связи с `http://` при запуске не поднимаются и показываются на странице как «нужно связать заново».

### 6. iPhone

- `/ca.mobileconfig` — профиль с одним сертификатом CA (`com.apple.security.root`), без подписи.
- Инструкция на стартовой странице: установить профиль → Настройки → Основные → Об этом устройстве →
  Доверие сертификатам → включить «Phonenect …».
- Команды не меняются (адрес вводится при добавлении); веб-клиент копирует адрес уже с `https://`.

### 7. Ошибки

- Не удалось создать сертификат — Phonenect не запускается и пишет причину (без HTTP-запасного пути).
- Отпечаток не совпал при подключении телефона или ПК — подключение отменяется с сообщением
  «Сертификат не совпадает — подключайтесь из дома и проверьте отпечаток на странице ПК».

## Проверка

- pytest: создание CA и сертификата сервера; все имена в SAN; перевыпуск при смене IP и близком конце срока;
  клиент с чужим CA не подключается; клиент с правильным CA и `check_hostname=False` подключается по другому IP;
  на порту 8766 нет `/api/*`, `/ws`, `/pair`; связь ПК по HTTPS с проверкой `fp`, отказ при неверном `fp`;
  профиль `.mobileconfig` — корректный plist с тем же сертификатом.
- JUnit: разбор `fp`, отказ ссылкам без `fp` и с `http://`, проверка отпечатка сертификата.
- Живая проверка: работающий Phonenect, запрос с правильным CA проходит, с системными CA — отказ.

## Не входит

- Шифрование файлов на диске ПК и истории в памяти.
- Отзыв токена и «доверенные сети» — следующие пункты (2–4) из списка улучшений, отдельными задачами.
